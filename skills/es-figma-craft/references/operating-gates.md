# Operating gates — how to think while doing Figma canvas work

Model-agnostic, project-agnostic. Read as **gates you must pass**, not advice to keep in mind. Every gate was generated by a real defect that shipped.

## 1. Verified means measured — never "looks right"

- Tool errors lie in both directions: a "connection lost" may have mutated the file; a clean return may have been rolled back. **After any ambiguous write, re-read state before reporting or retrying.**
- Screenshots are for humans. Geometry gets **numeric asserts** (e.g. per-column drift ≤0.5px), structure gets metadata reads, state gets property dumps.
- "Composed from components" is not correctness — **audit an atom's internals before building on it.** If the atom violates the rules, fix the atom's master first.
- Rendered screenshots report bounds INCLUDING effect bleed (drop shadows extend past the layout box). A reported height taller than the layout box is usually shadow bleed, not a gap — confirm via metadata before "fixing"; chasing a shadow can deform a correct layout.
- **Both layers can lie.** Node-reads miss render-level failures (dead propRefs, literal-drift); PNG crops can fake overlaps, and anti-aliasing can swallow glyphs (`~` read as `-`) at scale <1. When node-read and PNG disagree → measure `absoluteBoundingBox`; important text → read node `characters`, never the image.

## 2. Read before write; capture before destroy

- Cheapest read first: metadata → screenshot → full design context (last resort — response caps). Batch independent reads.
- Before instancing/replacing anything that carries data (table rows, overrides): **dump the content to JSON first.** Node replacement and variant switches reset overrides; you cannot recover what you didn't capture.
- Resolve by NAME, never cached id. Docs/registry are a *cache of intent*; the live file is the only structural truth — the owner edits it in parallel.

## 3. When something fails: isolate, don't iterate

- **Micro-test before retrying a failed batch call**: reproduce with one throwaway instance, probe the exact property, remove it. One cheap call beats three blind retries of a 150-line script. (Stack-trace line numbers have pointed at the wrong node.)
- Never assume partial success OR full failure of an errored call. Check.
- Root-cause before re-attempting: the bug *class* matters more than the bug ("cell width wrong" was really "instances default to HUG" — fixing one cell leaves the class alive in every table).
- 2 failed fix attempts on the same symptom → STOP, report BLOCKED with evidence. Do not improvise a third variation.

## 4. Fix the class, not the symptom

- Defect in an instance → suspect the master. Defect in a master → suspect the recipe. Fix at the highest level that owns the mistake, then **sweep for siblings carrying the same latent bug** (the second table "looked fine" and had the identical defect).
- **Sweep everything once, not per-complaint.** When the owner flags one cell/column/field, audit ALL of them in one pass before reporting done — owners should never have to ask the same question three times.
- Enhance-don't-duplicate: extend the existing component (new variant, TEXT prop, axis) instead of minting a sibling.
- Turn platform limitations into design decisions: "Figma can't override instance-sublayer geometry" became a stepped `Pct` variant axis — the limitation lives inside a component instead of a rule people must remember.
- **Verify a past rule's PRECONDITION before citing it to justify a shortcut** — a caution about "new property axis" does not block "new value on an existing axis". Don't reuse a conclusion by surface pattern-match.

## 5. One source of truth per fact — by construction

- Never generate the same geometry from two origins (cloning a header while composing rows = alignment by coincidence). One spec constant, one script, both artifacts.
- Scope components by reuse: generic pieces shared; per-context pieces own their specifics; data lives in instance overrides only.
- YAGNI as a sizing tool: build the variants today's data needs; note the deferred axis in the registry so it's a decision, not an omission.
- **Copy the MODEL, not the number.** Any measurement taken from another file must be understood via the formula that produced it, then recomputed for your kit (a reference's 1390px height was tallest+margin of THEIR type scale).

## 6. Ask when sources disagree; never delete what you didn't author

- Live code, docs, an old draft, and the user's screenshot can all legitimately differ. "More complete" ≠ "correct" — **surface the conflict and ask.**
- Stray content in a component you're editing may be the owner's parallel work. Flag, confirm, then remove.
- A value the owner has re-changed ≥2 times after you set it = **owner intent** — stop fixing, check the plan's decision ledger, ask once, lock the ledger.

## 7. Close the loop in the same change — or the lesson dies

- Every defect → its fix → a **hard rule** written into the project's patterns/gotchas + registry changelog (symptom → root cause → fix), in the same turn. Not "later."
- Write rules as executable checks where possible (drift asserts outlive prose discipline).
- The owner's catches are part of the quality system — convert each into a permanent rule and it compounds.

## 8. Respect the medium's concurrency

- One live file, one plugin/MCP connection, rate limits: mutations are **sequential**. Never fan out parallel agents against one Figma file.
- Rate limits follow the FILE's home team, not your seat.
- Mid-build directives to a running agent can silently drop — deliver directives as separate tasks when the agent is idle, or require an explicit ACK in the final report; no ACK = treat as dropped and verify by evidence.
- Multi-screen work = a plans/ checklist driven step-by-step with verification per step; batch conversions run sequentially with per-screen judgment.
